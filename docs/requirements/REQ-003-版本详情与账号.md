# REQ-003 版本详情页、账号与每版本设置

- 状态：已完成
- 提出：2026-10-21
- 相关：REQ-001（启动器骨架）、REQ-002（版本管理与加载器）

## 1. 要做什么

按用户原话整理（2026-10-21）：

1. 下载页点一个版本，**进入一个页面**（版本详情页），页面上能选模组加载器和加载器版本
2. 把「下载模组」（Modrinth 资源搜索）**从内容页搬到下载页**
3. 版本列表要**区分愚人节版本**
4. 主页**能添加账号**
5. 主页**不要推荐版本**
6. 点下载时有**详细的进度条**
7. 每个版本能**单独改东西**（现在改了不生效/没入口）
8. 「打开目录」要打开**版本目录**（`versions/<id>`），并**能选每次启动用哪个版本**
9. 有一个**版本设置页**，管理单个版本的内存 / Java / JVM 参数 / 隔离，模组也在这里管
10. **启动时有 cmd 黑窗一闪而过**（要修）

## 2. 不做什么

- 不做正版登录（微软账号 OAuth）；账号只做离线（昵称 + 本地生成的 UUID v3）
- 不做多账号同时在线，一次只有一个「当前账号」
- 不改 mods 的安装格式（DownloadAPI 仍是 Modrinth 直下 jar / zip）
- 不动启动器整体的视觉风格（沿用 0.10.0 的浅色卡片）
- 不做版本详情页里的「存档/截图」编辑，只列出来

## 4. 已知约束

- 窗口闪黑框：Windows 下 Rust 的 `std::process::Command` 拉起 console 程序会新建控制台，
  必须给每个调用点加 `creation_flags(0x0800_0000)`（`CREATE_NO_WINDOW`）。
  `launch::spawn` 和 `loader::run_java_raw` 已经有，**`java::detect` 漏了** —— 探测会遍历多个
  候选 Java，所以是「几个窗口一闪而过」。
- 愚人节版本在 Mojang 清单里仍标 `release`/`snapshot`，只能靠 id 白名单识别。
- 每版本设置后端早已实现（`dlp/version-settings.json`，`"*"` 为全局默认），缺的是 UI 入口。

## 5. 方案

**后端**

- `accounts.rs`：`dlp/accounts.json`（`{current, list:[{id,name}]}`），id = 离线 UUID
- `app.json`：`{default_version}`，主页选中的「每次启动用哪个版本」
- `VersionSummary` 增加 `april_fools`、`loader` 两个字段
- `open_version_dir(kind)` 的默认目标从「实例目录」改成 `versions/<id>`
- `java::detect` 加 `CREATE_NO_WINDOW`

**前端**

- 下载页：`版本 / 资源` 两个 tab；版本行点击进入详情视图（同类目下渲染，不换路由）
- 版本详情：基础信息、加载器（种类 + 版本）、OptiFine、详细进度、安装/启动、打开目录、版本设置
- 版本设置：内存 / Java / JVM 参数 / 隔离 + mods 列表（启用、删除、打开 mods 目录）
- 主页：实例卡里放「启动版本」下拉 + 账号切换 + 添加账号；去掉推荐版本
