# REQ-004 扁平化界面与中文模组搜索

- 状态：已完成
- 提出：2026-10-21
- 相关：REQ-003（版本详情与账号）

## 1. 要做什么

用户原话（2026-10-21）：

1. 「你这 UI 好简陋啊」→ 界面要**扁平化**：去掉渐变/发光/大圆角阴影那一套，改成实色 + 细边框
2. 「模组默认翻译为中文」→ 下载页「资源」里的搜索结果默认显示中文名（和中文简介）
3. 「搜索输入中文默认翻译为英文来搜索」→ 输入「钠」时按 `sodium` 查
4. 「搜索模组能以版本，模组加载器和类别区分」
5. 「先要选版本再选模组加载器」→ 资源页的筛选顺序：MC 版本 → 加载器 → 类别

## 2. 不做什么

- 不做机器翻译服务（不接 Google/DeepL，不联网翻译整段简介）：只查表，查不到就保留英文
- 不做 CurseForge 源，只继续用 Modrinth
- 不重做整套布局（导航结构、页面划分沿用 0.11.0）

## 3. 验收标准

| # | 标准 | 怎么验 |
| --- | --- | --- |
| 1 | 界面无渐变、无投影，卡片是 1px 实线边框 + 8px 圆角 | 截图对比 |
| 2 | 搜索 "sodium" → 结果标题显示「钠 / Sodium」这样的中文名（词典里有的条目） | 截图 |
| 3 | 搜索框输入「钠」→ 实际请求带 `sodium`（看后端日志/结果与英文搜索一致） | 截图 + 结果对比 |
| 4 | 资源页有「版本 / 加载器 / 类别」三个筛选，未选版本时加载器与搜索禁用 | 截图 |
| 5 | 选了版本 + 加载器后，结果只包含该组合可用的项目 | 结果与 Modrinth 网页一致 |

## 4. 已知约束

- Modrinth API 返回的 `title` / `description` 都是英文，没有 i18n 字段（待调研确认）
- 中文名只能靠「内置词典 + 可选远端词表」；词表拉不到时必须优雅退化成英文
- 加载器只能从版本 id 推断（原版 / fabric / quilt / forge / neoforge），没装加载器时按「任意」查

## 5. 方案

调研结论（2026-10-21，子代理实测）：

- **Modrinth API 没有本地化**：`/v2/project/` 带 `Accept-Language: zh-CN`、`?lang=zh` 三种请求响应 md5 完全一致，
  project JSON 43 个字段里没有 translations/i18n/locale，openapi.yaml 里 "language" 出现 0 次
- **没有可直接拉取的中文名 JSON**：CFPA 汉化包是 translation-key 表（不是 slug 表，仓库 >50MB，
  jsdelivr 列目录 403）；MC百科有中文名+简介但无公开 API、版权归站方；Modrinth 官方 zh-CN 只有 UI 文案
- 因此：**内置两份表**（项目中文名 + 中文→英文搜索词），查不到就退回英文

落地：

- `src/market_zh.rs`：`title_zh(slug, title)` 74 条、`translate_query(q)` 43 条，各带单测
- `market::search` 增加 `category` 参数（facets 加 `categories:<id>`），查询词先过 `translate_query`
- `Hit` 增加 `title_zh`，界面显示「中文名 + 英文原名」
- 资源页筛选顺序固定为 **版本 → 加载器 → 类别**，未选版本时后两者与搜索框禁用
