# REQ-001 跨平台 Minecraft 启动器（桌面端骨架）

- 状态：进行中
- 日期：2026-10-20
- 关联：REQ-002（文件中转站 / 镜像站，未开）

## 1. 要做什么

做一个自研的 Minecraft: Java Edition 启动器，能用微软正版账号或离线账号登录，能安装原版和 mod 加载器（Fabric / Forge / NeoForge），能启动游戏。跑在 Windows 10+、Linux x86_64、Linux arm64 上，界面要现代好看，安装包体积要小。

前端用 Vue 3 + Vite + TypeScript，核心逻辑用 Rust，桌面壳用 Tauri 2。

## 2. 不做什么

- **不做 Windows 7**：WebView2 对 Win7 的支持止于 Edge 109（2023-01），随包固定版运行时会让安装包 +60~90MB；且 MC 1.20.5+ 需要 Java 21，Java 21 本身不支持 Win7。详见 §5。
- **不做 macOS**：本期只覆盖 Windows + Linux。
- **不做整合包市场**：不接 CurseForge 商业 API，不做整合包浏览/一键安装。
- **不做游戏内功能**：不改客户端、不做 mod 开发。
- **不做文件中转站**：镜像站单独走 REQ-002，不混进本需求。
- **不做多语言**：界面先只做简体中文（代码里的文案集中管理，以后加 i18n 不返工）。

## 3. 验收标准

骨架阶段（M1）必须先满足：

| # | 验收项 | 怎么验 |
| --- | --- | --- |
| 1 | 核心库能独立测试 | `cargo test -p dlp-core` 全绿 |

| 3 | 桌面端能编译 | `cargo build -p dlp-desktop` 退出码 0 |
| 4 | 窗口能起来且 IPC 通 | `npm run tauri dev` 打开窗口，界面显示出 OS / 架构 / Tauri 版本 / 核心库版本 / 游戏目录 |

功能阶段（M2–M7）的验收标准在各自子需求里补，本文件只锁定骨架与边界。

## 4. 平台矩阵

| 平台 | 目标 | 打包产物 |
| --- | --- | --- |
| Windows 10 1809+ x64 | 一等公民 | NSIS `.exe` |
| Linux x86_64 | 一等公民 | `.deb` + AppImage |
| Linux arm64 | 一等公民（游戏侧待实测） | `.deb`（arm64） |
| Windows 7 / macOS | 不支持 | —— |

## 5. 已知约束（调研结论，2026-10-20）

1. **Rust 的 Windows 目标是 Windows 10 起步**，Win7 需要单独的目标三元组 `x86_64-win7-windows-gnu`（来源：[rustc platform-support](https://doc.rust-lang.org/rustc/platform-support.html)）。本机只有 MinGW 链路，走 `x86_64-pc-windows-gnu`。
2. **WebView2 在 Win7 的上限是 Edge 109**，微软 2023-01-12 终止支持；要支持 Win7 只能随包固定版运行时，安装包 +60~90MB。
3. **Java 21 不支持 Win7**，而 MC 1.20.5+ 必须 Java 21 —— 支持 Win7 等于把玩家锁在 1.16.5 及以下。
4. **Linux arm64 的两个未知数**：
   - Mojang 的 `java_runtime` 清单**没有 linux-arm64 条目**，arm64 上的 Java 必须从 Adoptium/Temurin 取。
   - MC 本体的 LWJGL natives 是否覆盖 linux-arm64 需实测；不覆盖的话「启动器能装能启动，但游戏跑不起来」。
5. **本机工具链**：MinGW-w64 gcc 16.2.0 + cargo 1.99.1，默认目标 `x86_64-pc-windows-gnu`，需要 ASCII 路径、NASM、`src-tauri/icons/icon.ico`。

## 6. 方案

```
Cargo.toml        workspace（members: src, src-tauri）
src/              dlp-core：清单 / 下载 / 校验 / Java / 启动 / 账号（纯 Rust，无 GUI 依赖）
src-tauri/        Tauri 壳：窗口、命令、capabilities、打包配置
ui/               Vue 3 + Vite + TS（构建产物 → 根目录 dist/）
```

- 核心与界面彻底解耦：`dlp-core` 不依赖 tauri，所有逻辑可在 CLI/单测里跑。
- 前端只做展示与交互，所有 IO 通过 `invoke` 走 Rust。

## 8. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| linux-arm64 上 MC 跑不起来 | 平台承诺落空 | M3 前先做一次 arm64 实机验证；不行就把 arm64 降级为「启动器可用」 |
| Forge 安装器必须靠 Java 运行 | M6 依赖 M5 | 先做 M5 再做 M6 |
| 未签名 exe 被杀软误报 | 用户装不上 | M7 评估代码签名证书 |
| MinGW 链路与某些 crate 不兼容 | 编译失败 | 保持 ASCII 路径；必要时切 MSVC 工具链（需另装 VS Build Tools） |
